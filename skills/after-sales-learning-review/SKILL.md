# 售后学习审核

把日常经验先变成候选，再由客服确认是否进入正式知识库。

## 处理用户指令

- `确认学习`：批准当前对话最近生成的候选；存在多个候选时先列出短摘要让用户选择。
- `不要学习`：拒绝当前对话最近候选并记录原因，避免重复提醒。
- `审核待学习`：运行 `scripts/review_learning.ps1 -Action List`，每次显示不超过 10 条。
- `批量审核`：先显示编号、产品、问题、建议规则和回复摘要，再按用户选择批准或拒绝。
- `撤销学习 <ID>`：追加撤销事件并重建正式案例索引。

## 候选标准

以下内容进入候选：新政策例外、人工修改后的最终回复、新赔偿边界、知识库未命中后成功解决的问题、新产品别名或可复用排查步骤。普通重复案例可以静默入队；高价值候选在日常回复末尾提示一次。

候选由 `scripts/new_candidate.ps1` 写入。只保存完成售后的必要摘要，去除顾客姓名、电话、地址、订单号和登录信息。

## 审核流程

1. 读取候选摘要和来源，确认它具有可复用价值且没有顾客敏感信息。
2. 需要修改时先展示拟修改内容，获得确认后再批准。
3. 运行 `scripts/review_learning.ps1 -Action Approve|Reject|Revoke -CandidateId <ID>`。
4. 运行 `scripts/sync_learning.ps1`。只有批准且未撤销的事件进入 `approved_cases.jsonl` 和快速检索层。
5. 报告处理数量、去重数量和正式案例总数。

每台电脑使用稳定 UUID `device_id`，事件使用独立 `event_id`。共享目录按设备追加写入，按 ID 和内容指纹去重，避免多电脑同时覆盖同一文件。
