# 使用案例

## 案例 A：在线表格模板查询

顾客原文：`充電できない`（无法充电）
用户说明：这是 06 switch 手柄

处理步骤：
1. 打开缓存目录（用户提供的根目录下的 `_售后模板缓存`）。
2. 读 `products.tsv`，按别名“06手柄”定位到 `switch手柄（楚腾飞）` 行。
3. 读 `faq/switch手柄（楚腾飞）.json`，匹配“无法充电/充電”条目，取 `template` 字段作为日文回复。
4. 检查 `facts/switch手柄（楚腾飞）.json` 是否有充电指示灯补充信息（06 充电时闪烁、充满长亮）。
5. 输出：命中依据 + 可直接发送的日文回复 + 内部处理要点（换线→拍视频→发新）。

参考回复模板（来自 FAQ）：
```
お客様
お世話になっております。お問い合わせいただきありがとうございます。
SWコントローラーが充電できない問題について、お手数ですが以下をご確認いただけますでしょうか。
充電ケーブルが正しく接続されているか？
ほかのケーブルに変更してみていただけますでしょうか。
もし充電ケーブルを交換しても解決できない場合、充電できない動画をこちらにご送信いただけますでしょうか。

```

## 案例 B：本地说明书查询

顾客原文：`バリカンの使いかたは？`（理发器怎么用）
用户说明：这是 GTS-6030 理发器

处理步骤：
1. 读 `products.tsv`，定位 `GTS-6030理发器（楚腾飞）`。
2. 读 `faq/GTS-6030理发器（楚腾飞）.json`，匹配“使い方/使用/锁机/注油”条目。
3. 读 `pdf_ocr/` 中对应说明书文本，找“使いかた”“各部のなまえ”章节补充细节。
4. 需要配图时，从 `pdf_pages/楚腾飞/理发器/` 取对应页面图（如第8页使いかた、第5页各部名称）。
5. 输出：分步使用方法 + 可发送日文回复 + 页面图路径（可选）。

## 案例 C：WPS 表格内嵌图片查询（VIO 部位图）

顾客问：`VIOに対応できますか`（是否支持 VIO 部位）
用户说明：这是 S1 冰点脱毛仪

处理步骤：
1. 读 `faq/S1冰点脱毛仪（肖玲）.json`，命中“VIO对应说明”条目，取 `template` 作为日文回复；
2. 该条目带 DISPIMG 图片（ID_E03B97595DA84E4A84753F5DF74BC49C），查 `xlsx_image_index/images.tsv`：
   - 工作表 `S1冰点脱毛仪（肖玲）`、单元格 `W38`
   - 本地 xlsx 内文件 `xl/media/image950.jpeg`
3. **先报位置给用户**（表格名+单元格/图片ID），默认不下载；
4. 用户明确要求“把图发给我”时，用 `build_xlsx_image_index.py --extract ID_... --out <文件>` 解出图片，并提示“整表 300MB，本次只解单张，较快”；
5. 输出：命中依据 + 可直接发送的日文回复 + 图片位置；需要时附图片文件。

## 案例 D：说明书图片识别（识图链路）

场景：需要判断某张说明书页图的内容（如 S1 说明书第几页有 VIO 部位图）

处理步骤：
1. 查 `manual_image_index/pages.tsv`，按 pdf_base 列出各页图路径；
2. 需要语义描述时，查 `vision_index/images.tsv`（已预索引则直接取描述）；
3. 未索引时运行 `build_vision_index.py --source manual --filter "<说明书基础名>" --limit N`；
4. 识图顺序：**优先本会话识图能力** → 不具备时脚本自动使用 vision-skill（qwen）→ vision-skill 未安装则提示“本会话不具备识图能力，需安装 vision-skill 接入第三方 API”。

## 案例 E：非产品类问题（售后原则 / 刷单原则 / 各注意事项）

场景：顾客或运营提出非产品类问题，例如“超过质保期能否退货”“刷单数量怎么登记”“晚班必做事项是什么”

处理步骤：
1. 判断为非产品类问题后，**不走产品 FAQ/说明书流程**，直接查三个固定工作表；
2. 运行 `quick_query.ps1 -Q "<关键词>"`（不指定 -Product 即全库扫描，会命中 kdocs 层），或直接读 `kdocs/售后原则.txt` / `kdocs/刷单原则.txt` / `kdocs/各注意事项.txt` 原文；
3. 命中后按“内部规则 → 可发给顾客/执行的回复”组织输出：
   - `售后原则`：退货/退款/质保/延保/换新等政策，涉及顾客回复时按表内政策生成日文回复；
   - `刷单原则`：内部操作规则，输出给操作员执行，不直接发给顾客；
   - `各注意事项`：早晚班工作习惯、必做事项、LINE 回复模板，输出给操作员执行。

示例：顾客问“買って3ヶ月以上経ちましたが、故障したので返金してもらえますか？”
1. 跑 `quick_query.ps1 -Q "3个月"` 或读 `kdocs/售后原则.txt`；
2. 命中“（三）订单>3个月，产品故障，买家要求退货退款”政策；
3. 按政策组织：原则上仅可发新品/部分退款（按购买时间折扣），若买家不接受则全额退款，并生成对应日文回复。

## 案例 F：产品参数查询（规格书 PDF / 参数层）

场景：顾客问“电热毯的电源线多长”

处理步骤：
1. 运行 `quick_query.ps1 -Product "电热毯" -Q "电源线 长度"`；
2. 命中 OCR/SPEC/PARAMS 层：
   - OCR：`肖玲\电热毯\规格书\单人产品规格书-MZM-5526-星盟版` page=4 → “電源側コード長 1.8M / 本体側コード長 0.6M”；
   - OCR：`肖玲\电热毯\规格书\双人产品规格书-MZM-8026-星盟版` page=4 → “電源側コード長 1.8M / 本体側コード長 1.2M”；
   - PARAMS（人工核验种子）：`param_seeds:电热毯（肖玲）` → MZM-5526 電源側 1.8m / 本体側 0.6m。
3. 若规格书是扫描件且 OCR 只读出 “18m/12m” 这类近似值，优先采信 `quick_index/param_seeds.tsv` 人工核验行；新参数可在该表追加后运行 `build_quick_index.py` 重建。
4. 输出：命中依据 + 可直接发送的日文回复（例：`電源コードの長さは電源側1.8m、本体側0.6mでございます。`）。

通用提示：`quick_query.ps1 -Diagnose` 未命中时会输出 `CANDIDATE_IMAGES`，可直接用列出的页面图做定向识图，不必重新找文件。

## 通用提示

- 优先使用 `faq` 模板原文，不要自行改写模板内容；只在模板缺失时基于说明书整理。
- 内部处理要点（如“确认视频后发新”）只给用户看，不发给顾客。
- 若产品名在 products.tsv 中找不到，先检查是否有别名（06/05/SW 等），再考虑增量更新。
- 日常文字问答默认用 `quick_query.ps1` 单命令快查（内部固定使用 Codex 自带 Python），命中即答；未命中再按“主动告知 + 可选深入”流程处理。
- 文字类问题不读取 300MB 本地 xlsx；只有涉及图片才查 xlsx_image_index，且默认先报位置、按需取图。
- OCR 检索必须先去除空格再匹配关键词（WinRT OCR 常输出逐字加空格文本）。
- 产品类问题先分类再检索；非产品类问题直接查 `售后原则 / 刷单原则 / 各注意事项` 三个表。
- 快查支持混合检索：同义词扩展 → 精确匹配 → 模糊匹配（rapidfuzz）→ BM25 排序；未命中可加 `-Diagnose` 查看分层诊断。
