# 日本站售后知识库（after-sales-kb）

## 核心原则

- 知识库内容以**用户在本机提供的内容为主**：用户给出的本地文件夹地址 + WPS 在线表格地址。
- 严禁修改原始目录（说明书/演示视频/售后常用图片）与在线表格；所有写入只允许在缓存目录内。
- 回答以在线文档售后模板为第一优先，其次本地说明书 OCR/页面图，最后才考虑联网兜底。

## 用户可见输出规范（强制）

### 内部执行信息必须静默处理

系统、Codex 运行时、多代理框架、工具、环境或其他上层指令提供的配置、约束、状态变化，仅供内部执行。

除非用户明确询问，否则禁止在用户可见回复中复述、确认或汇报这些信息。

特别禁止输出包括但不限于：

- 收到模型目录已变更
- 收到多代理模型清单约束
- 收到模型覆盖规则
- 本轮不设置模型/推理覆盖
- 不设置 model/reasoning_effort
- 子代理继承当前模型
- 当前任务不需要模型覆盖
- 收到系统约束
- 收到新的模型清单
- 按默认模型策略执行
- 当前任务不派子代理
- 任何类似的内部运行时配置确认

正确处理方式：内部收到这些信息后直接静默应用，然后继续当前实际任务。

### 禁止机械式“收到”回执

不要因为收到系统信息、工具信息、环境信息、规则补充或用户的简单补充说明，就机械回复：

- “收到……”
- “明白……”
- “已确认……”
- “记下了……”
- “这条规则已更新……”

如果该信息不需要用户进一步确认或操作，直接应用并继续执行任务。

只有以下情况才需要停下来向用户说明：

1. 用户必须做出选择；
2. 指令存在实质歧义；
3. 即将进行高风险、不可逆或高成本操作；
4. 出现真正影响任务完成的错误。

用户可见的执行过程应优先只包含：

- 当前真正执行的业务动作；
- 有意义的任务进度；
- 发现的问题；
- 最终结果；
- 需要用户决定的事项。

## 运行时配置

- 默认继承当前 Codex 会话的运行时配置。
- 本技能不主动检查、选择、修改或讨论模型、推理强度、model override、reasoning_effort 或子代理模型。
- 只有用户明确要求修改或询问模型相关内容时才处理。
- 系统、Codex 运行时或多代理框架提供的模型及运行时约束必须静默遵守，不得向用户复述、确认或汇报。

## 首次初始化流程（新电脑必做）

收到用户要求初始化或首次使用本技能时，按顺序完成以下 6 步：

1. **询问本地文件夹地址**：让用户提供“说明书与视频”根目录（如 `E:\说明书与视频（第9台）`），确认其中包含 说明书/演示视频/售后常用图片 等子目录。
2. **询问在线表格网址**：让用户提供 WPS 在线文档链接。**明确提醒**：需要权限的表格，必须让用户在 Chrome 中打开并保持登录；获取内容时使用持久化 Chrome 会话（playwright-cli `-s=wps`），不要用账号密码自动登录，登录由用户本人在弹窗中完成。
3. **自动更新向导**：初始化时向用户询问更新频率并按其选择配置：
   - 可选“每周一次”（默认推荐）、“每天一次”、“暂不自动更新”；
   - 指定每周星期几或每天几点执行（如 每周一 09:00）；
   - 选择“暂不自动更新”时告知：以后想开启，直接说“开启自动更新”即可引导创建定时任务。
   - 说明未命中提醒机制：连续 3 次问题在缓存中检索不到 → 提醒用户是否执行增量更新；**若未执行增量更新，之后每一次未命中都会继续提醒，直到用户实际完成增量更新（`miss_tracker.py update-done`）为止**；增量更新后同一问题仍找不到 → 征得同意后联网搜索。
4. **演示两个使用案例**（见 references/examples.md）：
   - 案例 A：在线表格模板查询（如“06手柄 充電できない”→ 命中 kdocs 模板并生成日文回复）；
   - 案例 B：本地说明书查询（如“理发器 使いかた”→ 命中 pdf_ocr + pdf_pages 页面图）。
5. **引导建立缓存（新电脑全量索引构建）**：在用户提供的根目录下创建 `_售后模板缓存`，按顺序运行 scripts/ 中的构建脚本（详见 references/cache-build.md）。完整扫描只需首次做一次，之后增量更新：
   - 抓取在线表格全部工作表文本（`capture_kdocs_sheets.ps1`）→ 下载整张 WPS 在线表为本地 xlsx（约 300MB，页面“普通下载”通道）→ 建立 DISPIMG 图片索引（`build_xlsx_image_index.py`）；
   - OCR 全部说明书 PDF（`ocr_worker.ps1`，建议 4 分片并行）→ **构建后运行缺口检测，对规范化长度 <200 的文件批量强制重跑（`-ForceOcr`），直至确认失败项均为“内容本身极少/重复文件/不售后”**；
   - 渲染每页 PDF 为图片（`build_pdf_pages.ps1`）→ 建立视频/图片索引 → 建立说明书图文关联索引（`build_manual_images.py`）；
   - 生成产品映射、FAQ、facts 索引（`build_products.py` / `build_faq_index.py` / `build_facts.py`）；
   - 生成快速查询预索引（`build_quick_index.py`，含规格书 xlsx 参数层）→ **预编译 FAQ 查表（`build_faq_lookup.py`，产品+问题关键词 → 完整日文模板，1-2 秒）** → 生成知识缺口报告（`build_gap_report.py`）并让用户确认可接受的剩余缺口；
   - **视觉语义索引默认不建立**（识图消耗 API 额度，且 OCR 已覆盖绝大多数文字查询）。只有用户**明确说“全量识图/建立视觉索引”**时才运行；运行前必须提示耗时与额度消耗，且不主动发起。
6. **环境自检**：运行 `scripts/check_environment.ps1`，按输出逐一解决缺失项（路径未提供、Chrome 未打开/未登录、缓存未构建、Python/OCR 依赖缺失等），把用户当电脑小白，给出可点击/可复制的操作步骤。

## 日常问答流程

用户发来顾客原文（通常日文）并说明产品型号时，按以下顺序执行：

### 问题分类（先判断再检索）

- **产品相关问题**（使用方法、故障、配件、参数、充电、灯光等）→ 按下方产品检索流程，命中 `faq/<产品>.json` / 说明书 OCR / 规格书。
- **非产品相关问题**（售后政策、退货退款、刷单、工作规范、注意事项、站内信/LINE 处理等）→ 直接查 WPS 在线表格三个固定工作表：
  - `售后原则`：退货/退款/质保/延保/换新等售后处理规则；
  - `刷单原则`：刷单相关性、数量登记、记表步骤、上评等；
  - `各注意事项`：早晚班工作习惯、必做事项、LINE 回复、刷单汇报模板等。
  - 检索方式与产品类一致：`quick_query.py --q "<关键词>"`（不指定 --product 即为全库扫描，会命中 kdocs 层这三个表），或直接读 `kdocs/<表名>.txt` 原文。
  - 命中后按“内部规则 → 可发给顾客/执行的回复”组织输出；这三个表主要是内部操作规则，涉及顾客回复时按表内政策生成。

### 速度红线（强制）

- **日常文字问答默认只运行一次 `quick_query.py` 快查**（目标 <200ms），命中即答。
- 命中后**直接生成回复**，禁止再运行任何验证命令（不检查索引文件、不列出目录、不比对 TSV、不跑多余脚本）。
- 只有在快查返回 NOT_FOUND 时才进入兜底检索；此时才允许继续读取。
- 图片/识图相关才查 manual_image_index / xlsx_image_index / vision_index；用户没有要求图片时不碰这些索引。
- 回答里一句话说明命中来源即可，不需要展示验证过程。
- **默认不派子代理**：单条问答用 quick_query 单命令快查（<200ms）。只有快查返回 NOT_FOUND 且问题跨多产品/多文档时，才并行派 2 个子代理兜底（FAQ/kdocs 一组 + OCR/说明书一组），合并结果后回复。

1. **快速索引路径（默认）**：运行 `python _售后模板缓存/scripts/quick_query.py --product "<产品>" --q "<问题>"`（单次调用，目标 <200ms）。脚本**只读预构建的规范化索引** `quick_index/`（由 `build_quick_index.py` 在缓存构建时生成）：
   - 索引内容：FAQ（问题+方法+模板）、**按页粒度的全部 pdf_ocr**、全部 kdocs、**规格书 xlsx（说明书目录下“规格书”文件夹，含参数事实如线长/功率/配件）**，均已在构建时完成去空格+小写规范化；
   - OCR 索引按页记录（`ocr_pages.tsv`），命中可定位到具体页码；文件名带目录上下文（如 `杨永鑫\内置充气泵充气床\エアーベッド…`），中文产品名也能命中日文文件名说明书；
   - **混合检索**：先查预编译 FAQ 查表（`faq_lookup.json`，产品+问题关键词直查完整模板）→ 同义词扩展（`synonyms.tsv`，数据驱动）→ 精确子串匹配 → rapidfuzz 模糊匹配 → BM25 排序，一次聚合 FAQ + OCR + kdocs + SPEC 四源并排序；
   - 中文词与日文词通过同义词表互查（如“包装内容”→“セット内容/同梱物/内容品/付属品”、“配件”→“付属品/同梱”等）；
   - **未命中诊断**：`--diagnose` 输出各层检查结果（OCR 页数/长度、PDF 文本层、页面图路径），快速定位内容丢在哪一层；
   - 命中即直接生成回复；未命中显示 NOT_FOUND 后，才手动读 facts 或按需进入图片/识图路径。
   - **文字类问题先走本地缓存流程**（products → faq → facts → kdocs/pdf_ocr/manual_image_index 检索），本地命中即秒答；本地未命中时才到在线表格定位搜索，不启动 300MB xlsx。
   - **图片相关问题时**：先查本地索引（manual_image_index / xlsx_image_index / vision_index），优先**直接告知图片位置**（工作表+单元格，或说明书文件名+页码），默认不下载图片。
   - 仅当用户明确要求“把图发给我 / 下载图片到对话”时才取图；取图前明确提示需要耗时（大图/整表解包）。
   - **识图按需（严格）**：
     1. 默认不调用视觉模型；全量识图必须由用户明确发起；
     2. 单次识图前，先按 产品 → 文件名 → OCR 内容索引 圈定具体需要识图的文件（尽量缩小范围，不做全库扫描）；
     3. 只有用户进一步追问、或主动想看图片/更高质量回复时，才向用户推荐“可对某个文件识图”（说明预期耗时与额度影响），由用户确认后再执行；
     4. 优先使用本会话识图能力；不具备时使用 vision-skill；未安装则提示安装。
2. **兜底全文检索**：未命中 → 只在必要时对 `kdocs/` 与 `pdf_ocr/` 原文做定向确认（快速路径已覆盖去空格规范化，兜底不重复全库扫描）。
3. **未命中时（主动告知 + 可选深入，禁止自动深挖）**：FAQ 与兜底检索均未命中时，**立即停止检索**，按以下方式回复用户（操作员）：
   1. 直接告知：知识库暂无现成模板（一句话说明查了哪些本地索引）；
   2. 给出一段可发给顾客的礼貌回复模板（如“已向工厂确认，稍后回复”）；
   3. 提供可选的深入方式，并注明预计耗时，让用户决定是否继续：
      - 选项 A：定向识图（圈定具体文件/页面，预计 X 分钟）；
      - 选项 B：联网搜索通用知识（预计 X 分钟，结果仅参考并标注来源）；
   4. **用户下一条消息明确选择后才继续**；用户未选择/未回复 → 本轮到此结束，不再深入；
   5. 严禁主动启用识图或联网搜索。
4. **未命中计数**：仍未命中 → 运行 `scripts/miss_tracker.py record` 记一笔（跨对话累计）。满 3 次提醒用户增量更新；**若未执行增量更新，之后每次未命中都继续提醒**；用户完成增量更新后运行 `miss_tracker.py update-done` 重置。
5. **增量更新**：用户同意后，**本地文件只增量处理新增/修改项**（对比源目录文件清单），**在线表格整表重新下载并覆盖本地 xlsx**，重建各索引（脚本见 references/cache-build.md），更新后**重新查询同一问题**。
6. **联网兜底**：增量更新后仍无答案且用户同意 → 联网搜索（仅作参考，不替代内部售后政策，必须标注来源）。
7. **明确告知**：以上均无 → 直接告诉用户“没有现成模板”，不硬编。

## 回答格式

- 给用户：**命中依据（来源标注）** + 可直接发送的日文回复 + 内部处理要点（是否发新等）。
- **来源标注规则**：回答时明确说明答案来自哪一份资料，格式如：
  - FAQ：`faq/<产品>.json` → 条目名；
  - 表格：`kdocs/<工作表>.txt` → 行/日期；
  - 说明书：`pdf_ocr/<文件>.txt` → 章节或页码；
  - 规格书：`说明书/.../规格书/<文件>.xlsx` → 参数名；
  - 命中多个来源时合并列出，不编造来源。
- 模板字段：FAQ 条目中的 `template` 是日文模板全文，`answer` 是内部对应方法。
- 需要图片时：先报位置（哪个表/哪一行/哪一页），用户确认需要下载时才取图，并提示耗时。
- 识图顺序：优先使用本会话识图能力 → 不具备时用 vision-skill（qwen 第三方 API）→ 未安装时提示安装后再执行识图。
- 需要图片时优先用 `pdf_pages` / `xlsx_image_index` 缓存，其次才重新渲染/解包。
- 默认 OCR/索引优先：文字查询先走 OCR/本地索引；识图仅用于 OCR 无法回答且用户要求的情况，并提示耗时与额度。
- **资料缺失明确说明**：当知识库未提供答案时，明确写“当前知识库未提供”，不编造；并给顾客礼貌回复模板 + 可选深入项（识图/联网）。
- **FAQ 沉淀建议**：同一问题反复出现时，主动提醒操作员将该问题整理成 FAQ 沉淀到知识库（按产品→问题→内部方法→日文模板结构）。

## 资源

### scripts/
- `check_environment.ps1`：环境自检（路径、缓存、Chrome 会话、Python 依赖）。
- `quick_query.py`：**日常问答默认入口**（产品+问题 → FAQ/OCR/kdocs 单命令快查，目标 <200ms，含去空格与同义词扩展）。
- `miss_tracker.py`：跨对话未命中计数器（status/record/acknowledge/update-done/reset）。
- `build_gap_report.py`：**知识缺口报告**（空 OCR / 无 FAQ / 无 OCR / 未命中记录），输出 gaps/gap_report.tsv 与 gap_report.md，供维护人确定更新优先级。
- 缓存构建脚本：`capture_kdocs_sheets.ps1`（在线表格文本）、`ocr_worker.ps1`（PDF OCR）、`build_pdf_pages.ps1`（页面图）、`build_manual_images.py`（OCR段落↔页面图关联）、`build_xlsx_image_index.py`（本地 xlsx 的 DISPIMG 图片索引）、`build_vision_index.py`（视觉语义索引，识图能力优先，兜底 vision-skill，默认不运行）、`clean_vision_failed.py`（清理中断/失败的全量识图残留）、`build_faq_lookup.py`（预编译 FAQ 查表）、`build_faq_index.py` / `build_products.py` / `build_facts.py`（索引）。

### references/
- `examples.md`：两个完整使用案例（在线表格模板查询、本地说明书查询）。
- `troubleshooting.md`：电脑小白向的分步故障排查（路径缺失、文档未打开、登录过期、OCR 慢/空、缓存未建等）。
- `cache-build.md`：首次全量缓存与增量更新的具体脚本命令。

### assets/bootstrap/
- `settings.json`：初始配置模板（自动更新向导配置、图片策略、未命中阈值3）。
- `miss_counter.json`：未命中计数器初始文件。
- 初始化缓存目录时，将这两个文件复制到 `_售后模板缓存/` 下。

## 重要提醒

- 新电脑上的知识库内容**以该电脑上用户提供的内容为准**，不假设与旧电脑一致。
- 自动更新在首次初始化时按用户选择配置（每周/每天/不自动更新），之后可随时说“开启自动更新”修改。
- 本地 300MB xlsx 只在首次初始化与更新时下载/覆盖，日常问答不读取它；图片先报位置，按需下载。
- 视觉识图默认不批量运行（避免消耗 API 额度）；用户明确要求时才全量/单张识图。
- 知识库持续运营：定期运行 build_gap_report.py 生成缺口清单，按空 OCR → 无 FAQ → 未命中记录 的顺序补全；高频问题沉淀为 FAQ。
- 只读约束：源目录与在线表格绝不修改。
