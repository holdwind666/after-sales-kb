# 日本站售后知识库（after-sales-kb）

## 核心原则

- 知识库内容以**用户在本机提供的内容为主**：用户给出的本地文件夹地址 + WPS 在线表格地址。
- 严禁修改原始目录（说明书/演示视频/售后常用图片）与在线表格；所有写入只允许在缓存目录内。
- 回答以在线文档售后模板为第一优先，其次本地说明书 OCR/页面图，最后才考虑联网兜底。

## 首次初始化流程（新电脑必做）

收到用户要求初始化或首次使用本技能时，按顺序完成以下 6 步：

1. **询问本地文件夹地址**：让用户提供“说明书与视频”根目录（如 `E:\说明书与视频（第9台）`），确认其中包含 说明书/演示视频/售后常用图片 等子目录。
2. **询问在线表格网址**：让用户提供 WPS 在线文档链接。**明确提醒**：需要权限的表格，必须让用户在 Chrome 中打开并保持登录；获取内容时使用持久化 Chrome 会话（playwright-cli `-s=wps`），不要用账号密码自动登录，登录由用户本人在弹窗中完成。
3. **提示每周更新开关**：默认关闭；用户明确说“启用每周自动更新”后才配置定时任务。说明 3 次未命中提醒机制：连续 3 次问题在缓存中检索不到 → 提醒用户是否执行增量更新；增量更新后同一问题仍找不到 → 征得同意后联网搜索。
4. **演示两个使用案例**（见 references/examples.md）：
   - 案例 A：在线表格模板查询（如“06手柄 充電できない”→ 命中 kdocs 模板并生成日文回复）；
   - 案例 B：本地说明书查询（如“理发器 使いかた”→ 命中 pdf_ocr + pdf_pages 页面图）。
5. **引导建立缓存**：在用户提供的根目录下创建 `_售后模板缓存`，运行 scripts/ 中的缓存构建脚本（在线表格全表抓取、PDF OCR、页面图、媒体索引）。完整扫描只需首次做一次，之后增量更新。
6. **环境自检**：运行 `scripts/check_environment.ps1`，按输出逐一解决缺失项（路径未提供、Chrome 未打开/未登录、缓存未构建、Python/OCR 依赖缺失等），把用户当电脑小白，给出可点击/可复制的操作步骤。

## 日常问答流程

用户发来顾客原文（通常日文）并说明产品型号时，按以下顺序执行：

1. **快速索引路径**：读 `_售后模板缓存/products.tsv` 定位产品 → 读 `faq/<产品>.json` 匹配问题模板 → 读 `facts/<产品>.json` 找参数事实 → 需要媒体时按映射取页面图/视频。命中即直接生成回复，目标秒级。
2. **兜底全文检索**：未命中 → 在 `kdocs/` 与 `pdf_ocr/` 中按关键词检索原文。
3. **未命中计数**：仍未命中 → 运行 `scripts/miss_tracker.py record` 记一笔（跨对话累计）。满 3 次提醒用户增量更新；用户确认后运行 `acknowledge` 重置。
4. **增量更新**：用户同意后，对比源目录新增文件、重新抓取在线表格（脚本见 references/cache-build.md），更新索引后**重新查询同一问题**。
5. **联网兜底**：增量更新后仍无答案且用户同意 → 联网搜索（仅作参考，不替代内部售后政策，必须标注来源）。
6. **明确告知**：以上均无 → 直接告诉用户“没有现成模板”，不硬编。

## 回答格式

- 给用户：命中依据（哪个表/说明书哪一条）+ 可直接发送的日文回复 + 内部处理要点（是否发新等）。
- 模板字段：FAQ 条目中的 `template` 是日文模板全文，`answer` 是内部对应方法。
- 需要图片时优先用 `pdf_pages` 缓存页面图，其次才重新渲染。

## 资源

### scripts/
- `check_environment.ps1`：环境自检（路径、缓存、Chrome 会话、Python 依赖）。
- `miss_tracker.py`：跨对话未命中计数器（status/record/acknowledge/reset）。
- 缓存构建脚本：`capture_kdocs_sheets.ps1`（在线表格）、`ocr_worker.ps1`（PDF OCR）、`build_pdf_pages.ps1`（页面图）、`build_faq_index.py` / `build_products.py` / `build_facts.py`（索引）。

### references/
- `examples.md`：两个完整使用案例（在线表格模板查询、本地说明书查询）。
- `troubleshooting.md`：电脑小白向的分步故障排查（路径缺失、文档未打开、登录过期、OCR 慢/空、缓存未建等）。
- `cache-build.md`：首次全量缓存与增量更新的具体脚本命令。

### assets/bootstrap/
- `settings.json`：初始配置模板（每周更新默认关闭、未命中阈值3）。
- `miss_counter.json`：未命中计数器初始文件。
- 初始化缓存目录时，将这两个文件复制到 `_售后模板缓存/` 下。

## 重要提醒

- 新电脑上的知识库内容**以该电脑上用户提供的内容为准**，不假设与旧电脑一致。
- 每周自动更新默认关闭，只有用户明确启用才配置。
- 只读约束：源目录与在线表格绝不修改。
